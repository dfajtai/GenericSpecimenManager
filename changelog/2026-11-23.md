# 2026-11-23

## [x] Fix: `{index}` produced a double underscore (`report__01.csv`)

- **Status:** done in code; the path logic is unit-tested (`FreeIndexedPathTest`), the batch export itself is **not verified in Slicer**.
- **Cause:** `BatchProcessor._resolve_pattern_path` removed `{index}` from the pattern and then appended `_NN` before the extension, so the
  underscore was part of the suffix: `report_{index}.csv` -> `report_.csv` -> `report__01.csv`.
- **Fix:** `{index}` is held back as a token while `{column}` is resolved, then replaced IN PLACE by the lowest free two-digit counter
  (`core/paths.first_free_indexed_path`): `report_{index}.csv` -> `report_01.csv`, `stats-{date}-{index}.csv` -> `stats-2026-11-23-01.csv`.
  No separator is added; the number now sits where the pattern puts it (it used to be forced in front of the extension).
- **Behaviour change:** existing patterns with `{index}` now give a different name. `example_batch_and_markups.json` (`stats-{date}-{index}.csv`)
  used to give `stats-<date>-_01.csv`, now `stats-<date>-01.csv`. Two or more `{index}` in one pattern all get the same number.
- Docs: `docs/batch-export.md`, `docs/config-reference.md`, the Config Editor cheat sheet and the pattern tooltips.

## [x] Default crosshair behavior: CenteredJumpSlice

- **Status:** done in code, **not verified in Slicer** (`SetCrosshairBehavior` with the named constant; the enum names are the curated, unconfirmed list).
- **Request:** the workspace default should be "jump centered". History check: `OffsetJumpSlice` was the default from the first commit (c9fe4b9);
  `CenteredJumpSlice` has only been a dropdown choice since the Workspace tab (331e53f), never the default. The jump to the scan centre after a
  load (2026-10-20, `center_slices_on`) is a separate, fixed behaviour and is unchanged.
- **Change:** `definitions.DEFAULT_CROSSHAIR_BEHAVIOR = "CenteredJumpSlice"` is used by `utils/workspace.apply_workspace_settings` when
  `workspace.crosshair_behavior` is unset. Every study without that key now gets the centred behaviour; `OffsetJumpSlice` has to be set explicitly
  to keep the old one (`kamilla_config.json` does). Config Editor hint and tooltip, cheat sheet (Crosshair, Key reference) updated.
- **Open:** if `CenteredJumpSlice` is not a constant of `vtkMRMLCrosshairNode` in some Slicer version, `resolve_enum` logs a warning and leaves
  Slicer's own behaviour in place (see the roadmap item about verifying the enum lists).

## [x] Batch export tab: clearer names for the two segment filters

- **Status:** done in code, **not verified in Slicer** (Config Editor labels and tooltips only); committed as c04575a.
- **Report:** a user set the statistics filter and saw every segment exported to a file. Not a bug: `segments_filter` (files) and
  `stats_segments_filter` (statistics) are independent by design, and the code applies each correctly. Both fields were called *Segments filter*.
- **Change:** labels and tooltips only - *Segments to export* and *Segments in statistics*; the cheat sheet uses the same names. Keys and behaviour unchanged.
- **Considered and dropped:** merging both into one filter. Built, then reverted - the independent filters are a valid feature (statistics for a
  few segments, files for others). Do not merge them without a concrete need.
