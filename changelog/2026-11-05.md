## [x] Status dot: green again after a save

- **Status:** done in code; needs a look in Slicer.
- **Bug:** the dot next to the Active specimen stayed orange (unsaved) after Save / Ctrl+S.
- **Cause:** `GenericSpecimen.save()` writes through a temporary storage node that is not attached to the node, so Slicer's own
  `GetModifiedSinceRead()` flag was never cleared.
- **Fix:** `save()` remembers each written node's `GetMTime()` (`_saved_mtime`); `_node_has_changed()` compares with it after the
  first save (before that, the standard flag is used). New `GenericSpecimen.has_unsaved_changes()` (segmentation and/or markups) is
  used by the status dot (`specimen_table._specimenIsDirty`) and by the close question.
- **Open:** if Slicer or the Segment Editor modifies the segmentation node on its own after a save, the dot turns orange again.

## [x] Close active specimen: warn about unsaved changes

- **Status:** done in code; needs a look in Slicer.
- **Bug:** Close gave no warning when the segmentation / markups had unsaved changes.
- **Now:** with unsaved changes, Close first asks *Save and close* / *Close* / *Cancel* (`_confirmDiscardUnsaved()` in
  `gui/specimen_actions.py`); then the usual question follows (Yes / Yes, mark to review / Yes, mark finished / No). Without unsaved
  changes only the usual question is asked. If the save fails, the specimen stays open.
- A first version replaced the usual question with a four-button one; the maintainer asked for this two-step flow instead.

## [x] Default Threshold range per volume in the Segment Editor (implemented; see "Done" below)

- **Status:** implemented (see "Done" at the end of this section), **not verified in Slicer**. Decision: the key lives on `images[]`,
  edited in the Config Editor's *Edit advanced...* popup.
- **Goal:** when a volume becomes the Segment Editor's source volume, the Threshold effect's range is set to a range given for that
  volume in the config - the same moment the foreground / background follow the source volume (`SourceVolumeLayerKeeper`).
- **Config sketch (not a decision):** optional `segment_editor_threshold: {"min": 200, "max": 1500}` on an `images[]` entry
  (recommended: the image's other settings are there; the existing image `threshold` is a *display* threshold, hence the separate
  name). Alternative: a map `image name -> [min, max]` in the `segment_editor` block.
- **Scope:** per image, not per segment (a per-segment default image was rejected earlier). Images without the key: no change.
- **When:** after the specimen is loaded (for the first source volume) and on every source-volume change.
- **Read in the Slicer source (2026-11-05, GitHub `Slicer/Slicer` `main`, commit feb57a5; the used Slicer 5.12 itself was not checked):**
  - `SegmentEditorThresholdEffect.py`: the range is the effect parameters `MinimumThreshold` / `MaximumThreshold`
    (`scriptedEffect.setParameter(...)`); `setMRMLDefaults` gives 0 / 0.
  - `qSlicerSegmentEditorAbstractEffect.cxx`: a parameter is stored as an attribute `<EffectName>.<parameter>` on the
    `vtkMRMLSegmentEditorNode`, i.e. `Threshold.MinimumThreshold` / `Threshold.MaximumThreshold`; setting it emits the node's
    `EffectParameterModified` event.
  - `sourceVolumeNodeChanged()` of the Threshold effect (also called by `activate()`) sets the slider range to the volume's scalar
    range and **only overwrites the values when Minimum == Maximum** (not initialised yet). So values we write first are kept; nothing
    resets them on a source-volume change. Our values outside the volume's range would be clamped by the slider (not checked).
  - `qMRMLSegmentEditorWidget`: `effectByName("Threshold")` returns the effect object (it is what `activeEffect()` returns for the
    active one); the widget emits `sourceVolumeNodeChanged(node)`; `showSourceVolumeInSliceViewers()` puts the source volume into the
    slice views' background only if it is not already shown, and the widget has a property `autoShowSourceVolumeNode` (default true)
    - **idea:** `setAutoShowSourceVolumeNode(False)` may make most of the `SourceVolumeLayerKeeper` fix-ups unnecessary; not tried.
  - **Likely recipe (to verify in Slicer):** `effect = widget.effectByName("Threshold")`, `effect.setParameter("MinimumThreshold", min)`,
    `effect.setParameter("MaximumThreshold", max)` (the effect must already have the editor's parameter set node: true once the widget
    has a segmentation / source volume). Alternative without the effect object: `editorNode.SetAttribute("Threshold.MinimumThreshold", str(min))`.
  - **Still unverified:** whether the open Threshold options panel updates its slider from a parameter written while the effect is
    active (the effect reads the parameters in `updateGUIFromMRML`; the `EffectParameterModified` event should trigger it).
    Log what is set so a miss can be diagnosed from the Python console.
- **Touches (when built):** `core/config_model.py` (field) -> Images tab in `gui/config_editor/` -> `utils/segment_editor.py` ->
  `docs/config-reference.md`, the Config Editor cheat sheet, `CHANGELOG.md`.

### Done
- `core/config_model.py`: `SegmentEditorThreshold(min, max)`, `ImageConfig.segment_editor_threshold` (merges like the other image fields:
  defaults -> preset -> entry).
- Config Editor: *Edit advanced...* has a checkable group **Segment Editor: default Threshold range** (Min / Max); the Advanced column
  shows `SE-thr:min-max`.
- `utils/segment_editor.py`: `threshold_attributes()` (pure, tested) and `apply_threshold_range()` write `Threshold.MinimumThreshold` /
  `Threshold.MaximumThreshold` with `SetAttribute` on the Segment Editor node - deliberately **not** through the effect object (touching
  the live effect once froze the GUI, see the comment in `activate_segment_editor`). `SourceVolumeLayerKeeper` applies the range of the
  new source volume on each source change (`applyThresholdFor`), and `activate_segment_editor` for the first one.
- `GenericSpecimen._load` collects the ranges (image node ID -> name, range) and also hands off to the Segment Editor when only such
  ranges are configured (the `segment_editor` block may be empty).
- An image without the key leaves the range as it was; a range typed by hand is replaced when the image is picked again.
- **To check in Slicer:** that the Threshold panel's slider shows the written range (SetAttribute fires the node's Modified event,
  not `EffectParameterModified`), that the first source volume gets its range, and that switching the source volume switches the range.
  The log line `[SegmentEditor] Threshold effect range for '<image>': {...}` shows what was written.
