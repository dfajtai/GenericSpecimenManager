# 2026-11-05

## [x] Status dot: green again after a save

- **Status:** done in code; needs a look in Slicer.
- **Bug:** the dot next to the Active specimen stayed orange (unsaved) after Save / Ctrl+S.
- **Cause:** `GenericSpecimen.save()` writes through a temporary storage node that is not attached to the node, so Slicer's own
  `GetModifiedSinceRead()` flag was never cleared.
- **Fix:** `save()` remembers each written node's `GetMTime()` (`_saved_mtime`); `_node_has_changed()` compares with it after the
  first save (before that, the standard flag is used). New `GenericSpecimen.has_unsaved_changes()` (segmentation and/or markups) is
  used by the status dot (`specimen_table._specimenIsDirty`) and by the close question.
- **Open:** if Slicer or the Segment Editor modifies the segmentation node on its own after a save, the dot turns orange again.

## [x] Close active specimen: warn about unsaved changes

- **Status:** done in code; needs a look in Slicer.
- **Bug:** Close gave no warning when the segmentation / markups had unsaved changes.
- **Now:** with unsaved changes, Close first asks *Save and close* / *Close* / *Cancel* (`_confirmDiscardUnsaved()` in
  `gui/specimen_actions.py`); then the usual question follows (Yes / Yes, mark to review / Yes, mark finished / No). Without unsaved
  changes only the usual question is asked. If the save fails, the specimen stays open.
- A first version replaced the usual question with a four-button one; the maintainer asked for this two-step flow instead.
