## [x] Batch export: decimals of the segment statistics

- **Status:** done in code and unit-tested (`tests/test_numbers.py`); the Config Editor field and the batch run are **not verified in Slicer**.
- **Problem:** the statistics CSV could contain float noise, e.g. `0.50000000000001` instead of `0.5`. Intensities are summed in float32 and a
  voxel volume is a product of spacings, so the binary representation leaks into the printed value.
- **Change:** `batch_export.stats_precision` (`BatchExportConfig`, an int >= 0) - every float metric is rounded to that many decimals when the row
  is built (`BatchProcessor._add_stats_row`). A value within `WHOLE_TOLERANCE` (1e-6, absolute) of a NON-ZERO whole number is written as that integer
  whatever the setting (`5.0` -> `5`, `255.0000004` -> `255`; `0.5` stays `0.5`). Near zero nothing is snapped: a small value is rounded to
  the decimals like any other (`5e-7` stays `5e-07` with 9 decimals, becomes `0` with 6). `math.isclose` is used, as `core/` has no numpy. Unset = `definitions.DEFAULT_STATS_PRECISION` (6). An invalid value (negative, text, a bool)
  is logged and replaced by the default. NaN (empty ROI) and infinity are kept; `-0.0` becomes `0`.
- The rounding is in the new pure-Python `core/numbers.py` (`round_stat`, `valid_decimals`), listed in `CMakeLists.txt`.
- Config Editor, Batch export tab, Segment statistics settings: a small *Decimals* field (empty = default; a non-number is refused on save).
- Docs: `docs/config-reference.md`, `docs/batch-export.md`, the Config Editor cheat sheet (Segment statistics settings and Key reference), `CHANGELOG.md`.
- **Open:** 6 decimals is a guess at a sensible default; very small intensity values (float images with tiny ranges) may need more.

## [x] Batch export progress bar: `x / 151` for 150 specimens

- **Status:** done in code, **not verified in Slicer**.
- **Cause:** `BatchProcessor.run()` started the bar with `len(finished) + 1` steps - the extra one was for writing the report files - so the
  bar showed one more than the number of specimens.
- **Fix:** the bar now has one step per finished specimen; writing the reports only changes its text.
