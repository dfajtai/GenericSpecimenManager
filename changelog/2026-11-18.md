## [x] Batch export: rounding of the segment statistics (decimals and precision)

- **Status:** done in code and unit-tested (`tests/test_numbers.py`); the Config Editor fields and the batch run are **not verified in Slicer**.
- **Problem:** the statistics CSV could contain float noise, e.g. `0.50000000000001` instead of `0.5`. Intensities are summed in float32 and a
  voxel volume is a product of spacings, so the binary representation leaks into the printed value.
- **Change:** two separate settings in `BatchExportConfig`, applied when a row is built (`BatchProcessor._add_stats_row`):
  - `stats_decimals` (int >= 0, default `definitions.DEFAULT_STATS_DECIMALS` = 4): every float metric is rounded to that many decimals.
  - `stats_precision` (number > 0, default `DEFAULT_STATS_PRECISION` = 1e-6): an ABSOLUTE epsilon with two jobs. (1) A value within it of a whole
    number - zero included, so everything below the precision - is written as that integer (`255.0000004` -> `255`, `3e-7` -> `0`), whatever
    `decimals` is. (2) A value smaller than `decimals` can show (below 10**-decimals) but above the precision is not rounded to 0: it is rounded
    at the precision's resolution instead (`3e-5` with 4 decimals and 1e-6 -> `3e-05`; `1.23456e-5` -> `1.2e-05`). A value that is a whole number
    after the decimals rounding is an integer too (`5.0` -> `5`, `2.4` with 0 decimals -> `2`).
  The two are not the same: decimals say how much of a normal value is shown, the precision says what counts as noise and how deep small values go.
  An invalid value (negative, text, a bool, NaN) is logged and replaced by the default. NaN (empty ROI) and infinity are kept; `-0.0` becomes `0`.
- The logic is in the new pure-Python `core/numbers.py` (`round_stat`, `valid_decimals`, `valid_precision`), listed in `CMakeLists.txt`.
- Config Editor, Batch export tab, Segment statistics settings: a *Rounding* row with two small fields, *Decimals* and *Precision* (empty = default;
  invalid input is refused on save).
- Docs: `docs/config-reference.md`, `docs/batch-export.md`, the Config Editor cheat sheet (Segment statistics settings and Key reference), `CHANGELOG.md`.
- **Open:** 4 decimals / 1e-6 are guesses at sensible defaults; float images with a tiny intensity range may need more decimals and a smaller precision.

## [x] Batch export progress bar: `x / 151` for 150 specimens

- **Status:** done in code, **not verified in Slicer**.
- **Cause:** `BatchProcessor.run()` started the bar with `len(finished) + 1` steps - the extra one was for writing the report files - so the
  bar showed one more than the number of specimens.
- **Fix:** the bar now has one step per finished specimen; writing the reports only changes its text.
