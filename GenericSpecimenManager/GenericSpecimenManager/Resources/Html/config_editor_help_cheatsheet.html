📝 Workflow

  1. Open a config - opening this dialog from the main module pre-loads the config that is active there (you are usually editing the SAME config the module has open). Otherwise use New or Load from file...; both ask Save/Discard/Cancel first if the form has unsaved changes (the title bar shows a trailing * while dirty). Reload from disk re-reads the open file, e.g. after editing it elsewhere.
  2. Fill in the tabs, roughly top to bottom: General (CSVs, key columns), Images, Segmentation, then Markups, Workspace, Segment editor, Volume rendering and Batch export as the study needs them. Defaults / Presets holds settings shared by many images.
  3. Save config (or Ctrl+S while this window is active, quietly) - the config is always built from the tabs (the same logic as Manual edit config → Refresh), so stray text that is not in a field is never saved. The write is atomic and the previous version is kept as config.json.prev. When the dialog was opened from the main module, it then offers to load the saved config into the module.
  4. Manual edit config is a view of the form: hand edits there only count after Apply to form.

🛠 General

  • study_dir - base folder every relative path resolves against. Empty = the preseg CSV's own folder.
  • Key columns - the composite specimen ID, e.g. ID or ID,measurement - must exist, with matching values, in both CSVs. Use "Show CSV columns..." to check.
  • Table columns - which database.csv columns appear (and are editable) in the main module's table. Any column works, not just status.
  • Output dir pattern - where a specimen's own files (segmentation, markups, any image explicitly saved) live for interactive work: resolved per specimen (any key/database.csv/preseg.csv column in {braces}), used every time you load/save a specimen through the normal GUI ("Load selected specimen"/"Save progress"). This is different from Batch export's own root dir/Segment export pattern further down, which only apply during a headless Batch Export run and never touch interactive work - the two are independent, and either can be set without the other.
  • Status column - the database.csv column holding each specimen's status (any name, e.g. done; created if missing): 0 untouched, 1 in progress, 2 to review, 3 finished. The main module always shows it as the table's last column, headed Status.
  • Filtering - Group specimens by key (its key column sits on the same row) shows a group-select combo after Initialize Study, filtering the specimen table by the chosen Group-by key (e.g. batch); Filter by status (on by default) shows a status checklist above the table. Both are purely main-module viewing conveniences - they do NOT affect the Batch Export tab.
  • Auto-save database - auto_save_database: when on, database.csv is written after every table edit and the main module's "Save database CSV" button is hidden. Default off.
  • Factor columns - a table (Add factor column / Remove selected) turning any database.csv column into a checkbox (binary) or a level dropdown (multilevel, with its own comma-separated Levels field) in the main module's specimen table, instead of plain free-text editing. A level is always written to the CSV as its exact text - never a numeric index - so the file stays directly readable by anything else. Independent of Table columns above: a factor column only actually renders as a checkbox/dropdown if it's ALSO listed there.

📦 Batch export

  • Its own tab; one "Batch export" button in the main module (inside the Advanced Study Settings block, shown only when this is enabled) runs it once, against every specimen with status finished in the database, all in one pass, without opening the interactive viewer for each one.
  • Enable batch export - turns this whole tab on; nothing below runs otherwise (their values are kept either way, just unused while off).
  • Batch export root dir - the root every pattern below is anchored to: segment/markup files, and (unless absolute) the Segment export/Report/Markup summary patterns too. Empty -> study_dir; relative -> resolved under study_dir; absolute -> used as-is.
  • Placeholders the patterns below can resolve - each field further down says which of these it actually supports:
    • {column} - any key/database.csv/preseg.csv column value for that specimen
    • {date} / {time} / {datetime} - the current date/time (YYYY-MM-DD / HH-MM-SS / combined)
    • {index} - only when present in the pattern: a two-digit, _01-based counter inserted before the extension, picking the lowest suffix not already on disk, so an existing file is never overwritten
  • Batch operations:
    • Export segments - each segment written to its own labelmap file.
    • Custom segment statistics - volume, min/max/mean/median/std, percentiles, computed straight from Slicer's own segment export (handles overlapping segments correctly, no third-party file reader) - needs numpy installed, nothing else. Configured in "Segment statistics settings" below.
    • Export markups - each specimen's markups .mrk.json file, PLUS a per-specimen markups CSV (label, x, y, z - world/RAS position, read straight from the live markups node) automatically alongside it - no separate switch needed for that part.
    • Markup summary - needs Export markups above also checked. In addition to the automatic per-specimen markups CSV, combines every specimen's markup points into one or more CSVs (one row per point, key columns prepended) - configured in "Markup summary settings" below.
  • Segment export settings:
    • Reference image - the geometry every exported segment labelmap is built on. A dropdown of the Images-tab names (it follows the table), so you can just pick one.
    • Segments filter - comma-separated segment names to limit which segments get exported to a file; empty = all. "Use all segments" fills it from the Segmentation tab. Independent of the Segment statistics settings' own filter below.
    • Segment export pattern - per-specimen subfolder joined onto Batch export root dir above. Supports {column} only (not {date}/{time}/{datetime}/{index}), e.g. {batch}/{ID} routes different specimens into different subfolders just by referencing that column. Empty -> your key columns, joined.
  • Segment statistics settings:
    • Stats reference image(s) - one or more Images-tab names (comma-separated) to sample intensities from; "Use all loaded images" fills in every image in the Images tab. Each sample image gets its OWN stats row per segment (an image column joins the key/segment columns) - all must share the segmentation's geometry (a mismatched one is skipped with a warning).
    • Segments filter - a SEPARATE comma-separated segment-name filter, independent of Segment export settings' own filter above: which segments get a statistics row. A segment can be included here without being exported to a file, or vice versa. "Use all segments" fills it from the Segmentation tab.
    • Metrics - comma-separated: volume, min, max, mean, median, std, and/or percentile_<N> (e.g. percentile_25); leave empty for the built-in default, or "Insert default" to see/edit it.
    • Report pattern - a file path anchored directly to Batch export root dir above (NOT nested through the Segment export pattern). Supports all four placeholders above: {column}, {date}/{time}/{datetime}, and {index} (only if present - otherwise an existing file is overwritten as usual). Same final path = one shared CSV, different paths = separate files. Empty -> report.csv. Rows are ordered by key columns, then image, then segment name.
  • Markup CSV coordinate encoding - RAS (default) or LPS, applied to the point x/y/z values written to BOTH the per-specimen markups CSV (from Export markups) and the combined Markup summary CSV below. The .mrk.json file itself is untouched either way. RAS is Slicer's own world coordinate, written as-is; LPS flips x and y (LPS = -x, -y, z relative to RAS) - use it if the CSV feeds an ITK/DICOM-based pipeline that expects LPS.
  • Markup summary settings (only used when "Markup summary" is checked; needs Export markups checked too):
    • Markup summary pattern - a file path anchored directly to Batch export root dir above (NOT nested through the Segment export pattern). Supports all four placeholders above: {column}, {date}/{time}/{datetime}, and {index} (only if present - otherwise an existing file is overwritten as usual). Same final path = one shared CSV, different paths = separate files. Points are read straight from each specimen's live markups node (label + world/RAS position) - NOT re-parsed from the .mrk.json file's stored "orientation" field, which is a display-only local axis frame (or, at the file level, just the LPS/RAS sign convention), not a per-point transform to apply on top of position. Empty -> markups_report.csv. Rows are ordered by key columns, then label.

🖼 Images

  • Quick add from preseg columns... - a popup listing one row per preseg CSV column (key columns excluded). Check Add to include a column as an image row; check Labelmap if it's a mask/label image instead of a regular volume. Then Add checked columns.
  • Where an image's file comes from - its CSV column value for that specimen if it has one; otherwise the Default path pattern (the field above the table, defaults.image.path_pattern): a {column} pattern over any key/database.csv/preseg.csv column, plus {name} (the row's Name), relative to Study dir. A single row can carry its own pattern in Edit advanced... → Path pattern.
  • Row order - on the Images and Segmentation tabs, Move up / Move down shift the selected row (the order is the load / segment order); the button is greyed out when the row is already first / last.
  • Images that are not in the preseg CSV - only the rows in this table are ever loaded (extra preseg columns are ignored). To add another image by hand, add a row with just a Name and leave CSV column empty: the Default path pattern finds its file, e.g. {ID}_{measurement}_{name}.nii.gz or {col1}/{col2}.nii.gz, as long as those columns exist. Initialize Study checks the column names against the CSV headers.
  • Role - background/label/foreground control slice-view layers (label/foreground also use Opacity). (none) = loaded but not shown as a layer.
  • Preset - a dropdown, populated live from whatever's currently in the Presets JSON field (Defaults/Presets tab). Add/rename a preset there and every row's list updates immediately, keeping each row's current selection if it's still valid.
  • Color table - gnuplot2 and inferno are the module's own matplotlib colour maps (black at the low end; combine with the Advanced Threshold to make values outside a range transparent). Also a dropdown grouped like Slicer's Colors module (Discrete, Shade, Tint, Continuous, FreeSurfer, PET, Cartilage MRI, Default labels from file), with the module's own maps first; pre-filled with common built-in Slicer color tables (Grey, Rainbow, the PET-* and Warm/Cool families, single-hue vtkMRMLColorTableNode* tables) - but it's editable, so type any other valid color node ID/name if yours isn't listed.
  • Edit advanced... - path pattern, window/level, threshold, Segment Editor threshold (the Threshold effect's starting range when this image is the source volume), interpolate for just that row. Rows with something set here are tinted and show a short summary in the Advanced column. The Effective settings box below the table always shows the actual merged result for the selected row.
1defaults.image - applies to every row
2named preset - only if that row's Preset column names one
3the row's own fields - always wins

🧠 Segmentation

  • Reference image - a dropdown of the Images-tab names (it follows the table); the pick is used as the geometry reference for the whole segmentation.
  • Path pattern - fallback naming for segment rows with no CSV column/path of their own, e.g. {ID}/{measurement}/{ID}-{segment_name}.nii.gz.
  • Opacity - display opacity of the whole segmentation (slice and 3D views), 0-1; empty = 1 (opaque). Multiplies with the fixed per-segment 2D fill opacity.
  • Visible - untick to hide a segment (slice and 3D views) when the segmentation is first built (a specimen without a saved segmentation yet), e.g. a helper segment; switch it on in the Segment Editor when needed. A saved segmentation is loaded as it is. Only the display changes. Ticked = Slicer's default, nothing is written to the config.
  • Source = file - tries CSV column / path pattern, falls back to an empty placeholder if nothing resolves. Source = empty - never tries a file, always a manual placeholder.

📌 Markups

  • Template file - if a specimen has no markups yet, this file loads as the starting point (renamed to that specimen) instead of an empty fiducial list.
  • Color - the markup point color: Set color... opens a color picker, Clear leaves Slicer's default.
  • Size - the markup point size: the Scale of Slicer's Markups display settings (e.g. 3 = Slicer's usual, larger = bigger points), or, with in mm checked, a real-world size in millimetres. Empty leaves Slicer's default.
  • Shape - the point glyph. Sphere3D is a real 3D ball: it is cut by each slice plane, so it shows across several neighbouring slices (as a shrinking circle) - best together with Size set in mm. The *2D shapes are flat markers seen only on the slice they sit on. (unset) leaves Slicer's default.

🖥 Workspace

  • Everything here is applied once, per specimen, to the 3D Slicer workspace itself - not to any data.
  • Window/level - blanket min/max for every loaded volume. Slice rotation - in-plane rotation (degrees) for Red/Yellow/Green, same as the Reformat module's slider; leave a view's field empty to leave it alone.
  • Crosshair - Mode/Behavior/Thickness dropdowns (editable - type the exact Slicer/VTK constant name if yours isn't listed). Leave at (unset) to keep this module's usual default (ShowBasic / OffsetJumpSlice / Fine).
  • Ruler - adds a scale ruler to every slice view. (unset) = leave alone.
  • 3D marker / 2D marker - the orientation-marker widget (Axes/Cube/Human) shown in the 3D view and/or every slice view - both use the same underlying property, configured independently. Volume rendering always shows a 3D marker (Axes/Large by default) regardless, unless overridden here.
  • View convention - Radiological (Slicer's own default: patient's right on screen-left) or Neurological (patient's right on screen-right). Only affects Axial/Coronal - Sagittal has no left/right to flip.
  • Specimen annotation (optional, workspace.specimen_annotation) - while a specimen is loaded, shows yellow text in the top-left of the Red/Yellow/Green and 3D views: the ID (key columns joined with -), a line, one column: value line per remaining Table column (the status column excluded), a line, and the status. Updates live as the table is edited; removed when the specimen is closed.

🖊 Segment editor

  • Modify other segments (overwrite_mode, in the Masking group) - Allow overlap (none) is the Segment Editor's "Allow overlap" checkbox; Overwrite all / visible segments (all_segments/visible_segments) restrict painting so it doesn't eat into other segments. (unset) leaves Slicer's own setting alone.
  • Editable area - where painting is allowed, like the Segment Editor's dropdown of the same name: everywhere, or only inside / outside all_segments / visible_segments. (unset) leaves Slicer's own setting (everywhere).
  • Use absolute size (mm) checked + shape sphere - fixed-size 3D brush in millimeters, regardless of zoom (e.g. always exactly 5 mm). Unchecked - size as a % of the slice view instead (grows/shrinks as you zoom).
  • Applied in two steps: at Study Init the defaults are set on the default/template node (used when the Segment Editor is opened for the first time this session) and on an already-live Segment Editor node, if there is one; and every time a specimen is loaded the module hands its segmentation to the Segment Editor, writes the brush settings, activates the Active effect and switches to the Segment Editor.
  • Show the source volume as the foreground - ticked (default): the source volume picked in the Segment Editor is shown as the foreground layer and the reference image stays the background. Unticked ("source_volume_to_foreground": false): the module does not touch the layers; Slicer's own behaviour applies (the picked source volume goes to the background, the foreground is cleared).
  • Editable intensity range - a range per brush effect (Paint, Erase): when that effect becomes active, the Segment Editor's Editable intensity range is switched on with these values (only voxels of the source volume inside the range can be changed), e.g. Paint -50..100, Erase -1024..-60. An end left empty = the source volume's own end; both empty = that effect does not touch the range. Slicer has one range for all effects, so it is rewritten whenever you switch between them.
  • Active effect on load - which effect (e.g. Paint) should already be selected. Left empty, the user just picks an effect manually - the brush size/shape above still applies whenever they pick Paint.

Raw attributes - what it's for and how to use it. Slicer stores each effect's settings as plain key/value pairs on the segment editor node. Common parameters shared by multiple effects (brush size/shape) have no prefix - just the bare name. Effect-specific parameters are prefixed EffectName.ParamName (a literal dot). Example dump of a real node's attributes:

BrushAbsoluteDiameter: 25
BrushDiameterIsRelative: 1
BrushSphere: 0
Paint.ColorSmudge: 0
Threshold.MinimumThreshold: 69.75
Threshold.AutoThresholdMethod: OTSU

So "attributes": {"BrushSphere": "1"} is correct; "Paint,BrushSphere" or "Paint.BrushSphere" is not a real key and silently does nothing. If a setting you configured through the structured fields above doesn't seem to stick, the fastest way to find the real key on your Slicer version:

  1. Open Segment Editor by hand, change the setting you want (e.g. tick "Sphere brush").
  2. Open the Python console and run: print(slicer.mrmlScene.GetFirstNodeByClass("vtkMRMLSegmentEditorNode"))
  3. Read the exact attribute name + value from the printed list, and add it under Raw attributes here (it's applied last, so it overrides the structured fields above if there's any conflict).

🌐 Volume rendering

  • One row per Images-tab image. Any number can have Enable checked at once - each gets its own independent 3D volume rendering.
  • Preset - a built-in Slicer VR preset name (editable combo - type your own if it's not in the list).
  • Min/Max - optional. Rescales the preset's opacity/color transfer function into that scalar range, e.g. narrowing a CT preset to a specific Hounsfield window for this specimen's data.
  • Offset - optional. Shifts the transfer function by a fixed amount, keeping its shape/spacing (classic "Shift" behavior). Wins over Min/Max if both are set.
  • Leave Min/Max/Offset all empty to use the preset exactly as shipped.
  • Refresh image list - re-syncs rows with the Images tab (new/renamed/removed images), keeping existing settings for images that still exist by name.

Note: the render itself is correct, but Slicer's own Volume Rendering module's "Shift" slider won't reflect the offset - cosmetic only.

🎨 Defaults / Presets

Three layers, merged in this order for every image (last one wins, per field):

1defaults.image – applies to every image row automatically
2the named presets[<name>] entry – only if that row's Preset column names one
3the row's own columns / Edit advanced... popup – always wins

Worked example. Say you're setting up a multi-sequence MRI study:

"defaults": {
  "image": { "type": "volume", "required": false, "interpolate": true }
},
"presets": {
  "mri_t1":  { "window_level": {"auto": true}, "color_table": "Grey" },
  "mri_flair": { "window_level": {"min": 0, "max": 400}, "color_table": "Grey" }
}

Now three image rows:

  • t1 → Preset = mri_t1, nothing else set. Effective: interpolate:true (from defaults) + window_level:auto, color_table:Grey (from the preset).
  • flair → Preset = mri_flair, but its own Advanced popup sets window_level: {min:0, max:600}. Effective: the row's own 0-600 wins over the preset's 0-400 - everything else from the preset still applies.
  • dwi → no Preset at all. Effective: just type:volume, required:false, interpolate:true from defaults - nothing else.

defaults.segment works the same way but one level only (defaults.segment → the segment row's own fields - segments don't have named presets).

A new config already starts with two starter presets (ct_soft_tissue, ct_bone) - edit or delete them freely. "Show example presets..." has a much bigger catalogue (CT/MRI/PET windows, colored overlays) to copy from, plus an "Insert ALL" button.

💾 Manual edit config

  • Refresh from form - regenerates the JSON box from every other tab's current state. This is exactly the JSON Save config would write - a live "what am I actually about to save" preview.
  • Apply to form - the reverse: parses whatever JSON is in the box and pushes it into every other tab (like Load from file, but from this text instead of disk). Handy for pasting in a config someone sent you in chat, or for a quick hand-edit of something with no dedicated field yet.
  • Save always saves from the tabs - if you hand-edit the JSON here, click Apply first, or your edits won't make it into the saved file.

Tip: select any text above (Ctrl+A / Ctrl+C) to copy it.

batch_export.export_segments / compute_stats / export_markups / markups_reportBatch export → Batch operationsWhich outputs a batch run produces. markups_report needs export_markups.
batch_export.reference_imageBatch export → Segment export settingsGeometry every exported segment label map is built on.
batch_export.stats_reference_images / stats_metricsBatch export → Segment statistics settingsThe images the intensities are sampled from (one row per image and segment) and the metrics (volume, min, max, mean, median, std, percentile_<N>); empty = the default set.
batch_export.output_dirBatch export → Batch export root dirThe root every batch pattern below is anchored to (segment/markup files, and any relative Segment export/Report/Markup summary pattern). Empty -> study_dir.
batch_export.output_dir_patternBatch export → Segment export patternPer-specimen subfolder, joined onto the batch root dir - governs segment + markup FILE export only.
batch_export.segments_filterSegment export settings → Segments filterWhich segments get exported to a labelmap file. Independent of stats_segments_filter.
batch_export.stats_segments_filterSegment statistics settings → Segments filterWhich segments get a statistics row. Independent of segments_filter - a segment can be in one, both, or neither.
batch_export.stats_output_pathSegment statistics settings → Report patternStatistics CSV path, anchored directly to the batch root dir (never nested through the Segment export pattern). Defaults to report.csv.
batch_export.markups_output_pathMarkup summary settings → Markup summary patternCombined markup-summary CSV path, same anchoring rule as the Report pattern. Defaults to markups_report.csv.
batch_export.markups_coordinate_systemMarkup summary settings → Markup CSV coordinate encodingRAS (default) or LPS - which convention the x/y/z values in the per-specimen markups CSV and the combined summary CSV use. Does not affect the .mrk.json file itself.
Placeholders in path patterns
{column}Any path-pattern fieldAny key/database.csv/preseg.csv column name in curly braces - substituted with that specimen's value.
{date} / {time} / {datetime}Report pattern, Markup summary patternCurrent date/time, substituted once per batch run (YYYY-MM-DD / HH-MM-SS / combined).
{index}Report pattern, Markup summary patternOnly when present: a two-digit, _01-based counter inserted before the file extension, picking the lowest suffix not already on disk - so a previous run's file is never overwritten. Absent -> existing file is overwritten as usual.
