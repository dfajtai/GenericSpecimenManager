📝 Workflow

  1. Pick the study config.json (Select .json file) - or build one with Config Editor... - in Advanced Study Settings.
  2. Press Initialize Study (the button between the two blocks; pastel green until you have). The specimen table fills; everything that needs an initialized study is disabled until this succeeds.
  3. Select a specimen row and press Load selected specimen: its images, segmentation and markups open in the configured layout.
  4. Segment / place markups, then Save progress for active specimen.
  5. Close active specimen - optionally marking it to review or finished on the way out.
  6. When specimens are finished, Batch export processes them all in one pass.

⚙ Study buttons and Advanced Study Settings

  • Initialize Study (its own button, between Advanced Study Settings and the Specimen browser) - loads the config and both CSVs and builds the specimen list. It is pastel green until a study is initialized, as a nudge to press it. Columns the config expects but database.csv lacks are offered for creation (the status and factor columns always; plain table columns only if ticked, as they may be typos). Once you confirm, the new columns are written to database.csv immediately.
  • Save database CSV - appears under Initialize Study once a study is initialized; writes the live table back to database.csv on demand. Hidden when the config has auto_save_database on: then database.csv is written to disk after every table edit.
  • Batch export - appears under Initialize Study once a study is initialized, but only if the config turns batch export on.
  • Advanced Study Settings (collapsed by default) - Study config (.json) is the active config; the field's border shows whether the path is missing, a folder or a valid file, and if it isn't a file, Initialize Study / Config Editor offer Browse, Open clean Config Editor or Cancel. Database / Preseg CSV override the two CSV paths in the config.

📋 Specimen table

  • One row per specimen. Click anywhere in a row to select it; the Selected specimen ID label follows the selection.
  • The columns are the config's Table columns. Plain columns are editable text; any of them can be written back to database.csv.
  • Factor columns: a binary factor is a checkbox (0/1), a multilevel factor is a dropdown of its levels.
  • The Specimen browser block holds the filters, the table and the load/save/close/reset buttons.
  • The last column is always Status (see below). The table is as tall as its rows, up to a cap, so the whole module never becomes scrollable.
  • The Group filter (if the config enables group by key) and the Status filter (a checklist - tick the statuses to show; all ticked = no filtering) narrow the table. Both sit at the top of the Specimen browser block and are viewing conveniences only - Batch export ignores them. The Group filter can't be switched while a specimen is loaded.
  • The coloured dot next to the specimen IDs: gray = selected but not loaded, green = loaded and saved, orange = loaded with unsaved segmentation/markups changes.
  • Optional specimen annotation (config: workspace.specimen_annotation): the loaded specimen's ID, table values and status as text in the views.

  • Automatic: 0 → 1 when a specimen loads from its own saved file or is saved. This never lowers to review / finished. Closing without changes leaves the status alone.
  • Manual: the dropdown in the table, or the buttons of the Close dialog.
  • Batch export processes only finished specimens.

💾 Load, Save, Close

  • Load selected specimen - one specimen can be active at a time. Close it before loading another.
  • Save progress for active specimen - writes its segmentation and markups (and any image you changed) into the specimen's output folder. Ctrl+S does the same, from any module, while a specimen is loaded (quietly, with a status-bar note); without a loaded specimen Ctrl+S is Slicer's own Save scene again.
  • Data safety - saves are atomic (a failed write never damages the old file), database.csv is backed up into a .backups folder and asks before overwriting a version changed on disk meanwhile, segmentation and markups keep the previous save as .prev, and a lock file warns when the study is open in another session. Details: docs/data-safety.md.
  • Close active specimen - never saves the specimen's work; save first if you want to keep it. The dialog offers Yes, Yes, mark to review, Yes, mark finished and No.

⚠ Reset selected specimen

  • Works on the selected row - the specimen does not have to be loaded.
  • Permanently deletes the specimen's saved segmentation and markups files and sets its status back to untouched. Source images are never touched.
  • The confirmation shows the specimen ID and the exact files; the button only enables after typing RESET. If the specimen is loaded, it is closed and unsaved work is discarded. This cannot be undone.

📦 Batch export

  • Runs once against every finished specimen, without opening the interactive viewer for each: segment files, custom segment statistics, markups files and a markup summary - whichever the config enables.
  • Everything about what it produces and where it writes is set in the Config Editor's Batch export tab.

🔑 Config

  • The whole study is described by one JSON file - use Config Editor... for a guided form; its own Help button has the full key reference.
  • The complete schema is in the Config reference (docs/config-reference.md in the repository).
